# Bruxa — Claude project notes

Apple Watch app that records wrist motion overnight and reports jaw-clenching (bruxism) episodes. iPhone companion shows the detailed report.

## Repository conventions

- **No Claude co-author in commits.** Do not append `Co-Authored-By: Claude ...` trailers. Do not add the "Generated with Claude Code" footer to PR bodies.
- Prefer small, descriptive commit subjects scoped by area, e.g. `feat(core): ...`, `refactor: ...`, `docs: ...`.
- Follow TDD as laid out in the foundation plan: failing test → implementation → green → commit.
- New logic lives in `BruxaCore` (Swift Package) so it runs under `swift test` on macOS. Platform-only adapters (CoreMotion, HealthKit, WatchConnectivity) live in `BruxaCore` behind `#if os(...)` guards; iOS/watchOS app targets stay thin SwiftUI shells.

## Layout

```

  Bruxa.xcworkspace        — open this in Xcode
  Bruxa.xcodeproj          — generated by xcodegen
  project.yml              — xcodegen source of truth
  BruxaCore/               — Swift Package, all domain + adapter logic
    Sources/BruxaCore/
    Tests/BruxaCoreTests/
    BruxaModel.xcdatamodeld  (source)
    BruxaModel.momd          (pre-compiled, regenerate with scripts/compile-model.sh)
  BruxaApp/                — iPhone companion target
  BruxaWatch/              — Apple Watch target
  BruxaAppTests/           — iOS test target
  BruxaWatchTests/         — watchOS test target

docs/superpowers/
  specs/                   — design specs
  plans/                   — implementation plans (TDD task lists)

scripts/
  compile-model.sh         — recompiles BruxaModel.xcdatamodeld → BruxaModel.momd
```

## Build & test

```bash
# Regenerate Xcode project after editing app/project.yml
cd app && xcodegen generate

# Run all BruxaCore tests (fast, no simulator needed)
cd app/BruxaCore && swift test

# Recompile the CoreData model after editing the .xcdatamodeld
./scripts/compile-model.sh
```

`swift test` is the source of truth for logic correctness. Simulator-based Xcode builds for `BruxaApp`/`BruxaWatch` require watchOS/iOS simulator runtimes — they are not required to verify core logic.

## Architecture quick reference

- **MotionProvider** — protocol over CoreMotion; `CoreMotionProvider` is the live adapter (iOS/watchOS only).
- **SleepStateProvider** — protocol with `ScriptedSleepStateProvider` (tests) and `HealthKitSleepStateProvider` (live).
- **SensorRecorder** — buffers 30 s motion windows, fan-outs to detector + (DEBUG-only) `PilotCSVWriter`.
- **EpisodeDetector** — protocol; current implementation is a stub. Real CoreML detector lands once the dataset path (EMG pilot vs heuristic MVP) is decided.
- **SleepSessionManager** — wires sleep state → recorder → detector → storage; the orchestration root on the Watch.
- **BruxaStorage** — CoreData over a pre-compiled `.momd` (SwiftPM can't compile `.xcdatamodeld`). Re-run `scripts/compile-model.sh` after edits or the runtime ships a stale model.
- **ConnectivityPayload / EpisodesBatch** — codable types crossing the Watch↔iPhone boundary.

## Working agreements

- Don't add features, abstractions, or error handling beyond what the current task requires.
- Don't add comments that just narrate code; only document non-obvious *why*.
- When a task needs Xcode GUI work (capabilities, entitlements UI tabs), pause and surface the manual step rather than guessing.
- Pilot CSV writer is `#if DEBUG` only — never enable it in release builds.
